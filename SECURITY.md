# PeoplePay360 — Security & RBAC Policy

---

## 1. Security Architecture & Threat Model

PeoplePay360 is engineered following the principle of **Least Privilege** and **Zero-Trust Backend Enforcement**. All permissions and authorizations are validated strictly server-side in FastAPI dependency guards, rather than relying merely on frontend visibility toggles.

---

## 3. Authentication & JWT Token Handling

- **Algorithm**: `HS256` HMAC-SHA256
- **Token Expiration**: Configurable (default: 60 minutes)
- **Password Hashing**: Cryptographic `bcrypt` with adaptive salt generation (`passlib[bcrypt]`).
- **Client Cache Sanitation**: On `logout()`, `localStorage` authentication tokens and active role states are cleared, and `queryClient.clear()` immediately scrubs cached financial and employee records from browser memory.

---

## 4. Input Validation & Injection Defenses

- **SQL Injection Prevention**: All database interactions use parameterized queries generated by SQLAlchemy 2.0 ORM.
- **Request Sanitization**: Pydantic v2 schemas rigorously validate types, emails, dates, and numeric wage constraints before entering business logic handlers.
- **Cross-Origin Resource Sharing (CORS)**:
  - Disallows permissive `allow_origins=["*"]` with credentials.
  - Dynamically enforces explicit origin allowlists (`settings.cors_origins`) and local development regex matching.

## 5. Security Reporting & Vulnerability Disclosure
